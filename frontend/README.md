# ATBA Frontend

Vite + React + TypeScript, calling only the REST interface provided by
[`../atba/api.py`](../atba/api.py) over HTTP — never importing Python code directly, frontend and
backend kept separate. All six pipeline steps have a corresponding page, rendering each step's real
audit trail step by step (thinking process/structured output/tool calls interleaved in the order they
arrived), driven live by the streaming endpoints.

## Running

Start the backend first (in a separate terminal):

```bash
pip install -r ../atba/requirements.txt
$env:ANTHROPIC_API_KEY = "sk-ant-..."   # or DEEPSEEK_API_KEY, depending on which provider you're testing
uvicorn atba.api:app --reload --port 8000
```

Then start the frontend:

```bash
npm install
npm run dev
```

The default backend address is `http://localhost:8000`; if the backend runs on a different port, copy
`.env.example` to `.env.local` and change `VITE_API_BASE_URL`.

## Production build

The compiled `dist/` output isn't checked into this repo (to avoid publicly distributing the backend
address baked in at build time). When deploying yourself:

```bash
VITE_API_BASE_URL=https://your-backend-domain.example npm run build
```

`vite.config.ts` refuses a production build that doesn't set this variable: running plain
`npm run build` (without `VITE_API_BASE_URL` set) fails the build outright with an error, rather than
silently producing a `dist/` that points every API request at `localhost:8000`. `npm run dev` is
unaffected — local development can still leave everything unset.

If frontend and backend are deployed behind the same domain via a reverse proxy, setting
`VITE_API_BASE_URL=""` makes requests go through the relative path `/api/...`; the backend's
([`../atba/api.py`](../atba/api.py)) CORS allowlist needs to include whatever frontend domain is
actually in use, kept consistent on both sides.

## Static demo build

`npm run build:demo` uses the separate [`vite.demo.config.ts`](vite.demo.config.ts) and doesn't connect
to any real backend — it uses a real completed run bundled into
[`src/demo-data/`](src/demo-data) as its data source; `src/api.ts`'s read-only GET requests resolve
directly from this bundle when `VITE_DEMO_MODE=true` (see the top-of-file comment in that file); the
output is inlined by `vite-plugin-singlefile` into a single `dist-demo/demo.html`, which can be opened by
double-clicking directly, without needing `npm run dev`/a backend. See
[`DEMO.md`](../DEMO.md) at the repo root for details.

## Routes

Every step has its own independent route, so past history can be reviewed; refreshing or visiting
directly only reads the result already persisted by the backend, never re-triggering a model call:

- `/` — start a new phenomenon input ([`src/pages/LandingPage.tsx`](src/pages/LandingPage.tsx))
- `/runs` — the run history list ([`src/pages/HistoryPage.tsx`](src/pages/HistoryPage.tsx))
- `/runs/:runId/step1` ~ `/runs/:runId/step6` — each step's result page; `run_id` is generated by the
  frontend at submission time (`crypto.randomUUID()`), so the URL is deterministic, shareable, and
  refreshable from the moment of submission
- The step 5 page (`Step5RunPage.tsx`) renders the whole step 4⇄5 loop as a sequence of turns grouped by
  "round N · step 4 or step 5"
- The step 6 page (`Step6RunPage.tsx`) doesn't show thinking/tool_call bubbles — the report body itself
  is the display content, with `text_delta` increments fed directly into the `ReportView` component for
  real-time rendering (with `remark-gfm` attached for rendering the appendix's tables + a custom Mermaid
  renderer for the theory-relationship diagram); a one-click `.md` export button sits at the bottom of
  the page

## Structure

- [`src/types.ts`](src/types.ts) — TS types kept manually in sync with the pydantic models in
  `atba/schemas.py`
- [`src/api.ts`](src/api.ts) — the backend REST client
- [`src/settings.tsx`](src/settings.tsx) — run-time settings shared across pages, such as
  provider/language (a React Context)
- [`src/pages/`](src/pages) — pages split by route (see the "Routes" section above)
- [`src/components/`](src/components) — `TranscriptView` (the chat-bubble list, reusing the same
  component both during streaming and after the run finishes), `ReportView`/`MermaidDiagram` (step 6's
  report rendering), etc.
